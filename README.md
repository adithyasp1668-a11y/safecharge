# FPGA-Based Adapter Safety Monitoring System

A prototype safety-monitoring system that combines an ESP32, a PYNQ-Z2 FPGA, voltage/current/temperature sensing, local indicators, and a live browser dashboard.

## Project overview

The ESP32 reads the sensors, calculates electrical measurements, checks safety thresholds, updates the LCD/LED/buzzer/relay outputs, and sends measurement packets over UART to the FPGA. The FPGA receives the UART stream, parses the voltage/current/temperature and status fields, and turns its LED on when a safety fault is detected. A Python Flask dashboard reads USB serial data from the ESP32 and displays measurements, safety status, and live trends in a browser.

## Files in this repository

| File | Purpose |
|---|---|
| `esp32_safety_controller.ino` | ESP32 firmware: sensors, LCD, buttons, relay, LEDs, buzzer, safety checks, and UART output to the FPGA |
| `fpga_safety_led.v` | Verilog module for UART reception, packet parsing, threshold checks, and FPGA fault LED output |
| `esp32_live_dashboard.py` | Python/Flask live dashboard that reads ESP32 USB serial data and plots recent measurements |

## Hardware used

- ESP32 development board
- PYNQ-Z2 FPGA board
- DS18B20 temperature sensor
- ACS712 current sensor
- Voltage sensor module
- Three potentiometers for voltage/current/temperature fault simulation
- 16×2 I²C LCD (address configured as `0x27`)
- Relay module, buzzer, green/yellow/red LEDs
- Push buttons for Start, Reset, Test, and Menu
- USB serial connection between the ESP32 and computer
- UART connection from ESP32 to PYNQ-Z2

## ESP32 pin configuration

| Function | ESP32 GPIO |
|---|---:|
| FPGA UART RX2 | GPIO16 |
| FPGA UART TX2 | GPIO17 |

| ACS712 analog output | GPIO35 |
| Voltage sensor analog output | GPIO32 |
| Voltage fault potentiometer | GPIO33 |
| Current fault potentiometer | GPIO36 |
| Temperature fault potentiometer | GPIO39 |
| Relay | GPIO26 |
| Buzzer | GPIO25 |
| Green LED | GPIO2 |
| Yellow LED | GPIO4 |
| Red LED | GPIO15 |
| Start button | GPIO27 |
| Reset button | GPIO14 |

**Important:** Check your board pinout and module voltage requirements before wiring. ESP32 GPIOs are not 5 V tolerant. Verify relay polarity and the sensor calibration for your actual hardware before relying on this as a safety device.

## Software requirements

### ESP32 firmware

- Arduino IDE
- ESP32 board support package
- `LiquidCrystal_I2C` library
- `OneWire` library
- `DallasTemperature` library

Open `esp32_safety_controller.ino`, select the correct ESP32 board and serial port, then upload it.

### FPGA design

- Vivado Design Suite (or the compatible FPGA toolchain used for your PYNQ-Z2)
- Add `fpga_safety_led.v` to your RTL sources
- Connect `clk`, `uart_rx`, and `led` to the appropriate board pins in your constraints file

The Verilog module assumes a 125 MHz clock and 115200-baud UART. Confirm the UART voltage levels, RX/TX direction, common ground, and the actual PYNQ-Z2 pin constraints before programming the board.

### Python dashboard

Install Python 3, then install the required packages:

```bash
python -m pip install flask pyserial
```

Connect the ESP32 to the computer by USB. Open `esp32_live_dashboard.py` and change `PORT = 'COM3'` to the ESP32's actual serial port if needed. Close Arduino Serial Monitor or any other program using the same port, then run:

```bash
python esp32_live_dashboard.py
```

The dashboard is configured to open at:

```text
http://127.0.0.1:5000
```

It displays voltage, current, temperature, power, sensor/fault status, potentiometer values, connection status, and live trend graphs.

## Safety thresholds configured in the code

| Measurement | Threshold |
|---|---:|
| Voltage fault | Above 5.5 V |
| Current fault | Above 7.5 A |
| Temperature warning | 32 °C or higher |
| Temperature fault | Above 40 °C |
| Fault potentiometer trigger | 90% or higher |

These are prototype code settings, not certified protection limits. Calibrate sensors and validate the design under controlled, low-risk conditions before connecting a real load.

## UART packet format

The ESP32 firmware sends FPGA packets at 115200 baud in this format:

```text
V=<millivolts>,I=<milliamps>,T=<centi-degrees-C>,F=<fault-0-or-1>,S=<sensor-ok-0-or-1>
```

The USB serial dashboard uses a human-readable line generated by the firmware. If the dashboard remains disconnected or shows zero values, compare the exact serial output and field names in the firmware with the parsing logic in `esp32_live_dashboard.py`; the parser and firmware must use the same line prefix and field names.

## Current project scope

This repository contains the ESP32 firmware, FPGA RTL module, and local dashboard script. It does not include a Vivado project, XDC constraints file, PCB design, test dataset, or a certified safety validation report.

## Disclaimer

This is an educational prototype and is not a certified electrical protection system. Do not use it as the only protection mechanism for mains voltage, high-current equipment, or safety-critical applications.
